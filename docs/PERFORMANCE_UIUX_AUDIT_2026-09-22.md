## 確認した問題と修正

| 優先度 | 問題 | 修正・根拠 |
|---|---|---|
| 高 | 押下と解放の両イベントでマクロが発火。0キーの単押しも二度押し扱いになり削除を実行 | イベント種別ごとに処理を登録。通常操作は押下時に一度、絶対複製・置換は従来どおり解放時に実行。`shortcuts/macros.lua:373` |
| 高 | プラグイン挿入でLiveの起動待ちが失敗しても入力を続行。連続選択・別アプリへの切替後にも遅延入力 | 保留タイマーと世代を管理し、各キー入力前に対象アプリとフォーカスを検証。無効化時にも中止。`shortcuts/rightclick.lua:199`、`lifecycle/appwatch.lua:13` |
| 高 | バージョン保存でキャンセル・メニュー選択失敗・フォーカス喪失後も名前を入力 | キャンセルと実際のメニュー操作結果を尊重し、古い処理を中止。正規表現のメニュー選択にも正しいフラグを渡す。`shortcuts/macros.lua:158`、`proccom.lua:198` |
| 高 | 設定保存中に追加した編集まで保存済み扱いになり、自動閉鎖で消失 | 保存時点の編集番号を照合し、後続編集は未保存として維持。保存後の自動閉鎖を撤去し、書込例外も失敗表示へ返す。`menus/settingsgui.lua:292` |
| 中 | キャッシュ保存成功でもLuaの条件式が常にエラー文字列を返し、スキャン完了画面へ進まない | 成功時のエラー値を明示的にnilにし、成功後の確認画面までテスト。`vst/scanner.lua:576` |

| 中 | 日本語カテゴリの文字列分割がUTF-8の途中で切れ、絞込名が文字化け | 区切り文字全体を検索して分割。検索画面の統計取得も1回に統合し、お気に入りの入れ子探索を名前索引に置換。`menus/chooser.lua:52`、`menus/chooser.lua:336` |
| 中 | AI応答の不正な構造、送信開始・JSON変換例外で完了通知に到達せず、UIが待機したままになる | 応答の各階層の型を検証し、開始失敗も終了コールバックへ返す。`ai/openai.lua:39` |

コード位置は `extensions/les/` からの相対パス。

## 性能に関する確認範囲

- 対象マクロの一押しあたりの発火は2回から1回に減少。イベントを送るテストで確認。
- ループ切替・バージョン保存のキー送信に残っていた既定200msの同期待機を0に変更。
  同梱の `extensions/eventtap/eventtap.lua:242` 以降にある実装で既定値を確認。
- VST3は51件のフィクスチャで、開始直後の同期読込0件、各処理最大12件、最終結果51件、完了通知1回を確認。
  全体のスキャン時間が短くなることを示す実測ではなく、連続したUI占有を減らす変更。
- 検索画面での `getAll()` 呼出しは3回から1回へ。もともと統計ファイルにはキャッシュがあるため、ディスク読込が3回から1回になったとは主張しない。
  お気に入りF件・プラグインN件の照合は O(F×N) から O(F+N) へ。
